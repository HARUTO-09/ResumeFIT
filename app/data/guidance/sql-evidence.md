Job descriptions that say "SQL" or "DBMS" want to know that you can design tables and write queries, not only that you took the course.

Evidence that works: a project that stores data in a relational database such as PostgreSQL, MySQL or SQLite; a schema you designed, with keys and an index you can explain; queries with joins, grouping and filtering that the application depends on; a migration or a script that loads and cleans data.

Write it as a result: "Designed a 6-table PostgreSQL schema and wrote the queries behind the usage dashboard." If you only used a CSV file, moving that project's storage to SQLite is a small change that gives you a truthful line and something to discuss in interviews.
