If a job description asks for Docker or cloud platforms and you have neither, you can earn a truthful line in a few days.

Docker: write a Dockerfile for a project you already have, build the image, run it, and fix what breaks. Learn what each line does, why a smaller base image helps, and why the app should not run as root.

Cloud: deploy that image, or the app directly, to a free tier of a hosting service. Note the steps, the limits you hit such as memory or cold starts, and how you set secrets through environment variables.

Then write exactly what you did: "Containerised the API with a multi-stage Dockerfile and deployed it to a free cloud tier." Do not write "experienced in AWS" after one tutorial; name the service and the task.
